Lezione 1.4 — Il concetto di algoritmo

Obiettivo: distinguere problema, algoritmo, programma ed esecutore e riconoscere le proprietà di una procedura ben definita.

Dalla situazione reale all'esecuzione

Problema → Analisi → Strategia → Algoritmo → Programma → Esecuzione.

L'algoritmo è la procedura generale che, ricevuta un'istanza valida, produce un risultato conforme alla specifica del problema.

Un esempio quotidiano

Una ricetta descrive una procedura: riceve ingredienti e quantità come input e, attraverso una sequenza ordinata di azioni, produce un piatto come output.

Un'indicazione come “cuoci per un po'” è ambigua; “cuoci per 20 minuti a 180 °C” è più precisa e può essere eseguita in modo ripetibile.

Definizione di algoritmo

Un algoritmo è una sequenza finita e ordinata di istruzioni non ambigue ed eseguibili che trasforma un input in un output.

Se un problema è descritto da (I, O, R), un algoritmo deve produrre, per ogni input valido i ∈ I, un output o ∈ O tale che (i,o) ∈ R.

Un percorso dall'input all'output

Caratteristiche essenziali

  • Generalità: risolve tutte le istanze appartenenti al dominio dichiarato.
  • Terminazione: conclude l'esecuzione dopo un numero finito di passi.
  • Efficacia: ogni istruzione è concretamente eseguibile dall'esecutore.
  • Non ambiguità: ogni passo ha un significato preciso.
  • Completezza: tutti i casi previsti dalla specifica vengono gestiti.
  • Riproducibilità: nel caso deterministico, gli stessi input producono lo stesso risultato.

Esistono anche algoritmi probabilistici; in questa fase del corso consideriamo algoritmi deterministici.

Algoritmo, programma ed esecutore

  • Algoritmo: procedura astratta, indipendente da uno specifico linguaggio di programmazione.
  • Programma: traduzione dell'algoritmo in istruzioni espresse in un linguaggio e destinate a un certo ambiente.
  • Esecutore: persona o macchina capace di comprendere ed eseguire quelle istruzioni.

Schema fondamentale: input → elaborazione → output.

Esempio: il Massimo Comun Divisore

Dati due interi non negativi a e b, non entrambi nulli, il Massimo Comun Divisore è il più grande intero positivo che divide entrambi senza resto.

L'operatore mod

Se b > 0, l'espressione a mod b restituisce il resto della divisione intera di a per b. Per esempio, 17 mod 5 = 2 perché 17 = 3 · 5 + 2.

Algoritmo di Euclide in linguaggio naturale

  1. Ricevi i valori a e b.
  2. Finché b ≠ 0, calcola il resto r = a mod b, poi assegna a a il vecchio valore di b e a b il valore di r.
  3. Quando b = 0, restituisci a.

Traccia di esecuzione: MCD(48,18)

(a, b) = (48, 18)   → 48 mod 18 = 12
(a, b) = (18, 12)   → 18 mod 12 = 6
(a, b) = (12,  6)   → 12 mod  6 = 0
(a, b) = ( 6,  0)   → risultato: 6

A ogni passo il MCD della coppia rimane invariato, mentre il secondo valore diminuisce fino a diventare zero.

Pseudocodice dell'algoritmo di Euclide

# Input: interi a, b ≥ 0, non entrambi uguali a 0
# Output: MCD(a,b)

funzione MCD(a, b):
    mentre b ≠ 0:
        r ← a mod b
        a ← b
        b ← r
    restituisci a

Perché è efficiente?

La correttezza descrive che cosa calcola l'algoritmo; la complessità misura quante risorse usa per calcolarlo.

Il secondo valore si dimezza almeno ogni due iterazioni

Dopo l'eventuale prima iterazione possiamo considerare una coppia (a,b) con a ≥ b > 0. Il valore b non supera quindi il minore dei due input iniziali. Dopo due iterazioni otteniamo:

(a, b) → (b, r) → (r, s)
r = a mod b
s = b mod r
  • Se r ≤ b/2, allora s < r ≤ b/2.
  • Se r > b/2, nella divisione di b per r il quoziente è 1; quindi s = b − r < b/2.

In entrambi i casi, dopo due iterazioni il nuovo secondo valore è minore della metà del precedente. Il numero di iterazioni cresce quindi in modo proporzionale a log(min(a,b)): la complessità temporale è O(log min(a,b)).

Il caso peggiore

I numeri di Fibonacci formano la successione definita da F0 = 0, F1 = 1 e Fn = Fn-1 + Fn-2 per n ≥ 2: 0, 1, 1, 2, 3, 5, 8, .... Le sequenze più lente per l'algoritmo di Euclide si ottengono con coppie di numeri di Fibonacci consecutivi. Anche in quel caso il numero di iterazioni cresce come Θ(log min(a,b)).

Quesito finale

Qual è la differenza tra algoritmo e programma? Quale ruolo svolge l'esecutore?

  • L'algoritmo descrive una soluzione generale indipendente dal linguaggio.
  • Il programma esprime quella soluzione in istruzioni adatte a un determinato ambiente, in un determinato linguaggio di programmazione.
  • L'esecutore comprende ed esegue le istruzioni e determina quali operazioni possono essere considerate elementari.
