Lezione 3.2 — Esercizi su IF/ELSE

Obiettivo: scegliere lo schema decisionale adatto, gestire i dati non validi e verificare ogni ramo con casi di prova mirati.

Metodo di lavoro

Per ogni esercizio costruisci prima il diagramma in Flowgorithm. Apri la soluzione soltanto dopo aver preparato almeno un caso di prova per ogni ramo.

1. Specifica
Individua input, output, vincoli ed estremi.
2. Casi
Elenca le situazioni che il programma deve distinguere.
3. Struttura
Scegli IF semplice, IF-ELSE, catena o annidamento.
4. Test
Prova dati validi, non validi e valori sui confini.

Pseudocodice del corso: ← indica l'assegnamento; = indica il confronto. Gli operatori ∧, ∨, ¬ corrispondono a and, or, not di Flowgorithm.

A — Condizioni composte

Esercizio 1 — Unione di due intervalli

Input
Un numero reale x.
Output
«interno» se x ∈ [-5,-2] ∪ [3,7], altrimenti «esterno».
Schema
Una condizione composta con AND e OR.

x = -3 → interno x = 0 → esterno x = 7 → interno

Prima di aprire: scrivi le due condizioni di appartenenza separatamente, poi uniscile.

leggi x
nelPrimo ← x ≥ -5 ∧ x ≤ -2
nelSecondo ← x ≥ 3 ∧ x ≤ 7

se nelPrimo ∨ nelSecondo allora
    scrivi "interno"
altrimenti
    scrivi "esterno"
fine se

Prova anche i quattro confini: -5, -2, 3, 7.

Esercizio 2 — Posizione di un punto

Input
Due coordinate reali x, y.
Output
«origine», «asse X», «asse Y» oppure il quadrante I, II, III, IV.
Schema
Catena ordinata di casi mutuamente esclusivi.

(0, 0) → origine (0, -4) → asse Y (-2, 5) → quadrante II

Prima di aprire: controlla l'origine e gli assi prima dei quadranti.

leggi x, y
se x = 0 ∧ y = 0 allora
    scrivi "origine"
altrimenti se y = 0 allora
    scrivi "asse X"
altrimenti se x = 0 allora
    scrivi "asse Y"
altrimenti se x > 0 ∧ y > 0 allora
    scrivi "quadrante I"
altrimenti se x < 0 ∧ y > 0 allora
    scrivi "quadrante II"
altrimenti se x < 0 ∧ y < 0 allora
    scrivi "quadrante III"
altrimenti
    scrivi "quadrante IV"
fine se

Qui x=0 e y=0 rappresentano coordinate inserite esattamente come zero.

B — Fasce e valori di confine

Esercizio 3 — Tariffa progressiva

Input
Consumo intero kWh ≥ 0.
Tariffe
0,20 € per i primi 100 kWh; 0,25 € dal 101° al 300°; 0,30 € oltre 300.
Output
Costo totale oppure un messaggio di errore se il consumo è negativo.

kWh = 80 → 16,00 € kWh = 250 → 20,00 + 37,50 = 57,50 € kWh = 320 → 20,00 + 50,00 + 6,00 = 76,00 €

Prima di aprire: in ogni fascia calcola soltanto la parte di consumo che vi appartiene.

leggi kWh
se kWh < 0 allora
    scrivi "consumo non valido"
altrimenti se kWh ≤ 100 allora
    costo ← kWh * 0.20
    scrivi costo
altrimenti se kWh ≤ 300 allora
    costo ← 100 * 0.20 + (kWh - 100) * 0.25
    scrivi costo
altrimenti
    costo ← 100 * 0.20 + 200 * 0.25 + (kWh - 300) * 0.30
    scrivi costo
fine se

Test minimi: -1, 0, 100, 101, 300, 301.

Esercizio 4 — Giorni del mese

Input
Anno intero positivo a e mese intero m tra 1 e 12.
Output
Numero di giorni del mese oppure un messaggio per i dati non validi.
Regola
Febbraio ha 29 giorni negli anni bisestili, 28 negli altri.

a = 2024, m = 2 → 29 a = 2100, m = 2 → 28 a = 2025, m = 13 → dati non validi

Prima di aprire: determina una sola volta se l'anno è bisestile.

leggi a, m
se a ≤ 0 ∨ m < 1 ∨ m > 12 allora
    scrivi "dati non validi"
altrimenti
    bisestile ← a mod 400 = 0 ∨ (a mod 4 = 0 ∧ a mod 100 ≠ 0)

    se m = 2 allora
        se bisestile allora
            giorni ← 29
        altrimenti
            giorni ← 28
        fine se
    altrimenti se m = 4 ∨ m = 6 ∨ m = 9 ∨ m = 11 allora
        giorni ← 30
    altrimenti
        giorni ← 31
    fine se

    scrivi giorni
fine se

Esercizio 5 — Valutazione in centesimi

Input
Punteggio intero p tra 0 e 100.
Output
«insufficiente» 0–59, «base» 60–74, «intermedio» 75–89, «avanzato» 90–100.
Vincolo
I valori esterni a 0–100 devono essere rifiutati.

p = 59 → insufficiente p = 75 → intermedio p = 101 → punteggio non valido

Prima di aprire: ordina le soglie dal valore più basso al più alto.

leggi p
se p < 0 ∨ p > 100 allora
    scrivi "punteggio non valido"
altrimenti se p < 60 allora
    scrivi "insufficiente"
altrimenti se p < 75 allora
    scrivi "base"
altrimenti se p < 90 allora
    scrivi "intermedio"
altrimenti
    scrivi "avanzato"
fine se

Il ramo p < 75 viene raggiunto dopo aver escluso p < 60: descrive quindi la fascia 60–74.

C — Annidamenti, guardie e casi speciali

Esercizio 6 — Mediana di tre valori distinti

Input
Tre numeri reali distinti a, b, c.
Output
Il valore che si trova tra gli altri due.
Vincolo
Non usare ordinamento, array, minimo o massimo predefiniti.

(9, 2, 5) → 5 (-1, 4, 10) → 4

Prima di aprire: un valore è mediano se è compreso tra gli altri due, in uno dei due ordini possibili.

leggi a, b, c
se a < b allora
    se b < c allora
        mediana ← b
    altrimenti se a < c allora
        mediana ← c
    altrimenti
        mediana ← a
    fine se
altrimenti
    se a < c allora
        mediana ← a
    altrimenti se b < c allora
        mediana ← c
    altrimenti
        mediana ← b
    fine se
fine se
scrivi mediana

Ogni percorso esegue al massimo tre confronti tra valori. Segui a mano, per esempio, il percorso prodotto da a=9, b=2, c=5.

Esercizio 7 — Conversione di temperatura

Input
Temperatura reale t e una String u contenente "C" oppure "F".
Output
Temperatura convertita nell'altra scala oppure «unità non valida».
Formule
F = C × 9 / 5 + 32; C = (F − 32) × 5 / 9.

t = 0, u = "C" → 32 °F t = 212, u = "F" → 100 °C t = 10, u = "K" → unità non valida

Prima di aprire: confronta una String con doppi apici; Flowgorithm non possiede un tipo Character separato.

leggi t, u
se u = "C" allora
    risultato ← t * 9 / 5 + 32
    scrivi risultato, " °F"
altrimenti se u = "F" allora
    risultato ← (t - 32) * 5 / 9
    scrivi risultato, " °C"
altrimenti
    scrivi "unità non valida"
fine se

In Flowgorithm la divisione / produce un valore reale. Quando tradurremo in C o C++, useremo costanti reali come 9.0 / 5.0.

Esercizio 8 — Dentro o fuori con De Morgan

Input
Tre numeri reali a, b, x.
Output
«interno» se x ∈ [a,b], «esterno» altrimenti; errore se a > b.
Richiesta
Scrivere il controllo dell'esterno e ricavare l'interno per negazione.

a = 2, b = 6, x = 2 → interno a = 2, b = 6, x = 8 → esterno a = 6, b = 2, x = 4 → estremi non validi

Prima di aprire: «esterno» significa sotto a oppure sopra b.

leggi a, b, x
se a > b allora
    scrivi "estremi non validi"
altrimenti
    esterno ← x < a ∨ x > b
    se ¬esterno allora
        scrivi "interno"
    altrimenti
        scrivi "esterno"
    fine se
fine se

¬(x < a ∨ x > b) equivale a x ≥ a ∧ x ≤ b.

Esercizio 9 — Multipli con priorità

Input
Un numero intero n.
Output
«multiplo di 6», «multiplo di 3», «multiplo di 2» oppure «nessuno».
Vincolo
Visualizzare soltanto la categoria più specifica.

n = 18 → multiplo di 6 n = 9 → multiplo di 3 n = 8 → multiplo di 2 n = 0 → multiplo di 6

Prima di aprire: il test più specifico deve precedere quelli che lo comprendono.

leggi n
se n mod 6 = 0 allora
    scrivi "multiplo di 6"
altrimenti se n mod 3 = 0 allora
    scrivi "multiplo di 3"
altrimenti se n mod 2 = 0 allora
    scrivi "multiplo di 2"
altrimenti
    scrivi "nessuno"
fine se

Lo zero è multiplo di ogni intero diverso da zero, perché 0 = k × 0. La categoria più specifica richiesta è quindi «multiplo di 6».

Esercizio 10 — Controllo di accesso

Input
Boolean autenticato, String ruolo, intero ora.
Regole
L'ora deve essere 0–23 e l'utente deve essere autenticato. Dopo l'autenticazione, l'accesso è consentito a "admin" e "docente" a ogni ora, agli altri ruoli soltanto tra le 8 e le 18 comprese.
Output
«accesso consentito», «accesso negato» oppure «ora non valida».

True, "admin", 22 → accesso consentito True, "studente", 10 → accesso consentito False, "docente", 10 → accesso negato True, "studente", 24 → ora non valida

Prima di aprire: valida l'ora, poi usa l'autenticazione come guardia prima di controllare i permessi.

leggi autenticato, ruolo, ora
se ora < 0 ∨ ora > 23 allora
    scrivi "ora non valida"
altrimenti se ¬autenticato allora
    scrivi "accesso negato"
altrimenti
    ruoloAbilitato ← ruolo = "admin" ∨ ruolo = "docente"
    fasciaOraria ← ora ≥ 8 ∧ ora ≤ 18

    se ruoloAbilitato ∨ fasciaOraria allora
        scrivi "accesso consentito"
    altrimenti
        scrivi "accesso negato"
    fine se
fine se

L'annidamento rende esplicito che i permessi vengono considerati soltanto per un utente autenticato.

Checklist prima della consegna

  • Ho dichiarato variabili con tipi coerenti con i dati?
  • Ho distinto l'assegnamento dal confronto?
  • Ho usato parentesi nelle condizioni composte?
  • Ho validato gli input quando la consegna impone un intervallo?
  • Le fasce sono complete, senza buchi o sovrapposizioni involontarie?
  • Ho eseguito il diagramma con almeno un dato per ciascun ramo?
